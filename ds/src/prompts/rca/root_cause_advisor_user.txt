Definitions:
- gaps: Missing or weak RCA elements in relation to the Problem statement and Analysis section.
- hypothesis: A specific, plausible root-cause hypothesis derived directly from an identified gap.
- task: A targeted analytical action that directly tests the hypothesis.
- assumptions: Minimal assumptions required because the provided Problem statement, Analysis section, or document text does not contain enough evidence.

Hypothesis-task requirements:
- Each hypothesis must link to a specific gap.
- Each task must directly test its corresponding hypothesis.
- Tasks must be specific and evidence-based, such as record review, log review, trend analysis, audit trail review, batch comparison, calibration verification, maintenance history review, environmental data review, sample traceability check, reconciliation review, training record review, or deviation linkage review.
- Avoid vague or generic actions such as "investigate further" or "check records."
- Do not propose CAPA, remediation, retraining, or corrective actions unless required solely to validate a hypothesis.
- Keep hypotheses narrow when evidence is limited.
- Do not fabricate details from the document.

Evidence discipline:
- Use only the provided Problem statement, Analysis section, Full document text, and Event type.
- Do not fabricate details.
- Do not infer facts that are not supported by the text.
- If evidence is limited, keep hypotheses narrow and state uncertainty only in assumptions.
- If the Analysis section does not provide enough evidence to rule out a plausible cause tied to the Problem statement, include that category.
- Prefer gaps that are directly connected to the stated problem over generic RCA gaps.
- If the Analysis section discusses a category only superficially, treat it as incomplete.
